# CMS для сайта вывесок

CMS на PHP 8.2+ / MySQL 5.7+ / Apache без сторонних библиотек. Архитектура — MVC.
Техническое задание — версия 1.0 (ноябрь 2026). Схема БД — [docs/db-schema.md](docs/db-schema.md).
Сценарии приёмки — [docs/acceptance.md](docs/acceptance.md).

## Требования к серверу

- PHP **8.2** или новее, расширения: `pdo_mysql`, `mbstring`, `fileinfo`, `dom`, `curl` (для скачивания фото при импорте CSV; без него используется `allow_url_fopen`), `openssl` (SMTP с шифрованием).
- MySQL **5.7** или новее (MariaDB не используется), пустая база в кодировке `utf8mb4`.
- Apache с `mod_rewrite` и `AllowOverride All` для каталога сайта.
- Права на запись у веб-сервера: папки `include/` и `uploads/` (со всеми подпапками), корень сайта (для `robots.txt`; иначе установщик покажет содержимое для ручного создания).

## Установка

1. Скопируйте файлы в корень сайта (`.htaccess` обязателен).
2. Откройте `https://ваш-домен/start.php` и заполните форму:
   - параметры базы данных;
   - адрес сайта (`https://domain.com`), логин и пароль администратора;
   - email получателя заявок и параметры SMTP (сервер, порт, шифрование SSL/STARTTLS, логин, пароль, адрес отправителя). Если SMTP-сервер не указан, письма отправляются функцией `mail()`.
3. Установщик создаст таблицы, системную категорию «Без категории», первый слайд, файлы `include/connect.php` и `robots.txt`.
4. **Удалите `start.php` с сервера.** Повторный запуск заблокирован, а админка показывает предупреждение, пока файл не удалён.
5. Админка: `https://ваш-домен/manet`.

## Смена пароля администратора

Формы смены пароля в админке нет (п. 3.3 ТЗ). Пароль хранится в `include/connect.php` в виде хеша.

1. Скопируйте `tools/passhash.php` в корень сайта.
2. Откройте `https://ваш-домен/passhash.php`, введите новый пароль и получите хеш (он нигде не сохраняется).
3. В `include/connect.php` замените значение переменной `$r08` полученным хешем (в одинарных кавычках).
4. **Удалите `passhash.php` из корня сайта.** Пока файл там, админка показывает предупреждение.

Назначение переменных в `include/connect.php` (имена намеренно нейтральные) описано в `include/classes/Config.php`.

## Структура

```
index.php             единая точка входа (все запросы через .htaccess)
start.php             установщик (удалить после установки)
.htaccess             ЧПУ, закрытие служебных каталогов
include/              конфигурация и ядро (закрыто от HTTP)
  connect.php         параметры установки (создаётся установщиком, в git не хранится)
  schema.sql          структура БД
  bootstrap.php       автозагрузка классов
  classes/            ядро (namespace Core): Db, Config, Urls (адреса и редиректы),
                      Html (фильтрация), Upload, Mailer (SMTP), Paginator, Settings...
  classes/Models/     модели: Category, Product, Property, Page, Section, Slide, MenuItem, FileItem
public/classes/       контроллеры публичной части (namespace Site)
public/templates/     шаблоны публичной части; parts/ — шапка, меню, подвал и т. п.
admin/classes/        контроллеры админки (namespace Admin)
admin/templates/      шаблоны админки
assets/               стили и скрипты (styles.css, script.js, calculator.js, product.js, admin.*)
uploads/              загруженные файлы (выполнение скриптов запрещено)
tools/passhash.php    получение хеша пароля (закрыт; копируется в корень при необходимости)
tests/                автоматические тесты
docker/, docker-compose.yml   тестовое окружение
```

Статичные блоки шаблонов (тексты, «Что мы изготавливаем», «Как работаем», отзывы, FAQ, калькулятор, реквизиты и т. п.) правятся в `public/templates/*.php` (п. 4.8 ТЗ).

## Тестовое окружение и автотесты

Нужен Docker. Окружение: PHP 8.2 + Apache, MySQL 5.7, Mailpit (тестовый SMTP).

```bash
docker compose up -d --build
```

Откройте http://localhost:8080/start.php и установите CMS с параметрами: хост БД `db`, база/пользователь/пароль `cms`, адрес сайта `http://localhost:8080`, SMTP-сервер `mailpit`, порт `1025`, без шифрования. Письма видны на http://localhost:8025.

Запуск тестов (**тесты пересоздают все таблицы БД** — только на тестовой установке):

```bash
docker compose exec -e CMS_TEST_ALLOW_RESET=1 -e CMS_TEST_ADMIN_PASS=<пароль администратора> web php tests/run.php
```

Тесты покрывают маршрутизацию, редиректы 301 и цепочки, уникальность адресов, фильтрацию HTML, доступ к админке (вход, блокировка, CSRF, cookie), каталог, пагинацию, активность, слайдер, меню, текстовые страницы, формы заявок (письма проверяются через Mailpit), загрузку файлов и импорт CSV.
